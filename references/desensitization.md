# RZCN 脱敏与痕迹清理

## 原则

- 只处理独立的材料副本，不修改正式源码。
- 脱敏以“恢复代码可读性、去除无关运行信息”为目的，不用于伪造作者、开发过程或规避审查。
- 具体业务标识可以保留；与登记材料无关的内部基础设施信息必须删除或替换。
- 扫描命中为零只能说明规则集未发现目标模式，不能证明代码作者或生成方式。

## 必须脱敏

| 类别 | 示例 | 处理 |
|---|---|---|
| 公网/内网 IP | 真实 IPv4、IPv6 | 替换为 `127.0.0.1` 之外的占位符或删除 |
| 域名/API | 管理台、下载站、私有 API 域名 | 用 `<接口地址>`、`<管理地址>` |
| SSH/部署 | 用户名、主机、端口、私钥路径、部署根目录 | 删除或泛化为“服务器部署路径” |
| 数据库 | URI、库名、账号、密码、连接串 | 只保留 `process.env.DATABASE_URL` 等变量名 |
| 凭据 | 管理 key、access key、token 示例、JWT、签名私钥 | 删除真实值，保留业务校验逻辑 |
| 个人数据 | 手机号、身份证、真实姓名、真实邮箱、用户 ID | 用 `130****0000`、`用户ID`、`contact@example.com` |
| 工作记录 | 自动化工作流、模型日志、提示词、内部计划、屏幕录制路径 | 删除，不进入源码副本或 PDF |
| 调试输出 | 本机绝对路径、内部主机名、调试 token、临时目录 | 删除或使用相对路径 |

## 推荐占位符

```text
<接口地址>
<管理地址>
127.0.0.1
contact@example.com
ADMIN_ACCESS_TOKEN
DATABASE_URL
USER_ID
```

占位符必须保持代码语法可解析。不要将真实密钥写入注释、日志、测试文件或提交说明。

## 自然维护风格边界

允许：

- 把空泛注释改成具体业务说明；
- 使用少量拼音局部变量，如 `yuanShiPiaoLiu`、`shijieLieBiao`；
- 保留兼容分支、局部修正和真实业务取舍；
- 删除过度整齐的模板式横幅。

禁止：

- 虚构 Git 提交、维护人员或评审记录；
- 故意写坏逻辑或降低安全性以“显得像人工”；
- 为规避检查制造假历史、假缺陷或假注释；
- 大范围重命名公共接口、数据库字段或跨模块契约。

## 建议扫描

源码副本和 PDF 提取文本至少扫描：

```text
IPv4/IPv6、真实域名、SSH/root、数据库 URI、
password/secret/access key/token 赋值、
BEGIN PRIVATE KEY、真实手机号、真实邮箱、
自动化工具名、日志工作流、提示词和内部部署路径
```

同时检查 PDF 元数据中的作者、标题、创建器、生产器和自定义字段。提交说明、报告和文件名也不得包含敏感值。
