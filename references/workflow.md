# RZCN 详细工作流

## 1. 先冻结事实

开始制作前，先建立事实表：

| 项目 | 要求 |
|---|---|
| 软件全称 | 与申请表、说明书、PDF 页眉一致 |
| 软件简称 | 不得与全称完全相同 |
| 版本号 | 统一使用 `V1.0` 或申请平台要求的格式 |
| 著作权人 | 只写申请人确认的主体 |
| 开发方式 | 单独开发、合作开发或委托开发必须有真实依据 |
| 完成日期 | 用申请人确认的日期 |
| 发表状态 | 未发表、已发表必须与事实一致 |
| 首次发表日期/地点 | 未发表通常填“无”或留空，平台强制时填“无” |
| 权利取得方式 | 原始取得或继受取得必须与合同、权属材料一致 |
| 权利范围 | 通常为全部权利 |
| 源码范围 | 明确目录、语言、文件数、总行数 |
| 文档范围 | 明确使用哪一种完整文档，不能拼凑互不一致的章节 |

申请人未确认的事实不得由模板推定。

## 2. 建立隔离目录

```text
材料根目录/
├─ 00_提交文件/                  # 最终上传 PDF
├─ 01_源码登记副本_脱敏/         # 程序材料工作副本
├─ 02_文档源稿_勿上传/           # 可编辑说明书
└─ 99_内部核对_勿上传/           # 脚本、文本提取、校验、预览
```

正式源码始终只读。不要把内部脚本、完整源码副本、工作记录或临时 PDF 放入上传目录。

## 3. 程序文件准备

1. 按登记的源码范围复制 Dart、TypeScript、Java、Kotlin 等实际源文件。
2. 统计原始文件数和行数，生成基线清单。
3. 只在副本中做：
   - 局部拼音变量名；
   - 与实际业务一致的口语化维护注释；
   - 移除模板式分隔线和空泛解释；
   - 替换敏感值。
4. 保持源文件行数不变，除非申请人允许材料副本改变统计口径。
5. 不伪造作者、Git 记录、评审记录、版本历史或多人协作痕迹。

推荐先构造一份按功能顺序拼接的纯文本源程序：

- 每行一条源码；
- 每个文件前加入 `// 文件：相对路径` 及分隔线；
- 保留所有源码行，但不要保留空行作为页行。
- 将大型纯字符串/法务文本块放到中段，避免后 30 页被低信息密度内容占满。

生成程序 PDF：

```powershell
python E:\CodexData\CodexHome\skills\rzcn\scripts\build_program_pdf.py `
  --source-text <拼接源码.txt> `
  --output <00_提交文件/程序鉴别材料.pdf> `
  --software "软件全称" `
  --version "V1.0"
```

脚本会：

- 对长行自动续行；
- 输出连续前 30 页和后 30 页；
- 每页固定 50 条显示行；
- 写入页眉、页码和页脚；
- 生成 PDF 元数据；
- 输出 JSON 摘要。

## 4. 文档文件准备

优先从可编辑 DOCX 或纯文本生成，不直接从旧 PDF 拼页。

- 文档不足 60 页：提交完整文档；
- 文档达到或超过 60 页：提交连续前 30 页和后 30 页；
- 每页至少 30 条实际正文行；
- 旧目录页码失效时必须删除或更新；
- 最后不足 30 行的页面不能靠重复文字填充，应增加真实附录、术语索引、安装说明或测试说明。

生成文档 PDF：

```powershell
python E:\CodexData\CodexHome\skills\rzcn\scripts\build_document_pdf.py `
  --input <说明书.docx 或文本文件> `
  --output <00_提交文件/文档鉴别材料.pdf> `
  --software "软件全称" `
  --version "V1.0" `
  --appendix <真实附录.txt>
```

## 5. 脱敏

同时扫描：

- 源码登记副本；
- 拼接后的程序文本；
- 文档输入；
- 最终 PDF 提取文本；
- PDF 元数据。

详细规则见 [desensitization.md](desensitization.md)。

## 6. 全量复核

```powershell
python E:\CodexData\CodexHome\skills\rzcn\scripts\audit_materials.py `
  --material-root <材料根目录> `
  --program <程序.pdf> `
  --document <文档.pdf> `
  --source-copy <源码副本> `
  --base-copy <整理前副本> `
  --expected-document-pages <页数>
```

必须检查：

- 页数；
- 每页物理行/正文行；
- 文字是否越界；
- 页面是否空白；
- 程序材料与源文本是否逐行一致；
- 源文件是否缺失、增加或行数变化；
- 敏感模式；
- 工具/自动化痕迹；
- PDF 哈希；
- 上传目录是否混入工作文件。

## 7. 交付

至少报告：

- 材料目录；
- 两份 PDF 的页数、行规则和哈希；
- 源码文件数、总行数和行数一致性；
- 脱敏扫描结果；
- 格式或语法检查结果；
- 申请人尚未确认的事实。
